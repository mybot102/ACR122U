# NFC 助记词离线备份系统

基于 NTAG216 + ACR122U 的安全助记词分片备份解决方案

## 📋 概览

这是一个完全离线的工具，使用 NFC 卡片进行助记词备份：

- ✅ 生成 1 份 AES-256-GCM 加密的助记词密文
- ✅ 将 AES 密钥进行 Shamir 3-of-5 分片
- ✅ 写入 5 张 NFC 卡：每张存储密文 + 1 份密钥分片
- ✅ 任意 3 张卡片即可恢复助记词
- ✅ 数据仅保存在内存中，不落盘
- ✅ 使用卡内数据（CardID + Counter + Challenge）识别卡片，不依赖 UID

## 🔧 硬件要求

### NFC 卡片
- **推荐：** NTAG216（7 张：5 张正式 + 2 张备用）
- **测试：** NTAG215（容量较小，仅用于流程验证）

### NFC 读写器
- **型号：** ACR122U（PC/SC 协议）
- **接口：** USB

## 💾 数据结构

每张 NFC 卡存储以下数据：

| 区域 | Pages | 大小 | 说明 |
|------|-------|------|------|
| CardID | 4-7 | 16 bytes | 卡片唯一标识符 |
| Counter | 8-9 | 8 bytes | 写入时间戳计数器 |
| Challenge | 10-17 | 32 bytes | 随机挑战值 |
| Encrypted Blob | 18-85 | 272 bytes | AES 加密的助记词 |
| Share | 86-105 | 80 bytes | Shamir 密钥分片 |

## 🚀 快速开始

### 1. 安装依赖

```bash
# 安装 Python 依赖
pip install -r requirements.txt

# 安装 PC/SC 驱动（如果尚未安装）
# macOS: 已内置
# Ubuntu/Debian:
sudo apt-get install pcscd pcsc-tools
# Windows: 从 https://www.acs.com.hk/ 下载 ACR122U 驱动
```

### 2. 启动服务器

```bash
python server.py
```

服务器将在 `http://127.0.0.1:8080` 启动（仅本地访问）

### 3. 打开 Web 界面

在浏览器中访问：`http://127.0.0.1:8080`

### 4. 备份助记词

1. 在"备份助记词"标签页输入您的助记词
2. 点击"开始备份"
3. 按照提示依次放置 5 张 NFC 卡片
4. 系统会自动写入加密数据和分片

### 5. 恢复助记词

1. 切换到"恢复助记词"标签页
2. 点击"开始恢复"
3. 依次放置任意 3 张备份卡片
4. 系统自动恢复并显示助记词

## 🔐 安全特性

### 加密机制
- **算法：** AES-256-GCM（认证加密）
- **密钥：** 256-bit 随机生成
- **Nonce：** 12 字节随机值（每次加密唯一）
- **认证标签：** 16 字节（防篡改）

### 密钥分片
- **算法：** Shamir 秘密共享
- **配置：** 3-of-5（5 个分片，任意 3 个可恢复）
- **分布：** 每张卡存储不同的分片

### 卡片识别
不依赖 UID（可伪造），使用卡内应用数据：
- **CardID：** 16 字节随机标识符
- **Counter：** 写入时的时间戳
- **Challenge：** 32 字节随机挑战值

### 内存安全
- 所有敏感数据仅存储在进程内存中
- WebSocket 断开时自动清空
- 服务重启时数据丢失（设计如此）
- 不写入任何日志或临时文件

## 📝 使用建议

### 安全存储
1. 将 5 张备份卡分散存放在不同的安全位置
2. 建议放置地点：
   - 家中保险箱
   - 银行保险柜
   - 信任的亲友处（不同地点）
3. 避免将所有卡片放在同一地点

### 定期检查
- 每 6 个月检查一次卡片可读性
- 使用"恢复助记词"功能验证
- 如发现卡片损坏，立即使用其他卡片恢复并重新备份

### 物理保护
- 避免卡片弯折、划伤
- 远离磁场和高温
- 可使用卡套保护

### 操作安全
1. **备份前：**
   - 确保系统完全离线
   - 关闭所有不必要的程序
   - 断开网络连接

2. **备份后：**
   - 清空浏览器缓存
   - 清空浏览器历史记录
   - 重启计算机（确保内存清空）

3. **恢复时：**
   - 同样确保系统离线
   - 在安全的环境中操作
   - 恢复后立即转移资产（如有必要）

## 🔍 故障排除

### 无法检测到读卡器
- 检查 USB 连接
- 确认驱动已安装
- Windows: 检查设备管理器
- Linux: 运行 `pcsc_scan` 检查

### 卡片读写失败
- 确认使用 NTAG216 卡片
- 卡片放置平稳，不要移动
- 清洁读卡器表面
- 尝试另一张卡片

### 恢复失败
- 确保使用的是正确的备份卡
- 至少需要 3 张不同的卡片
- 检查卡片是否损坏
- 尝试其他卡片组合

### WebSocket 连接失败
- 确认服务器正在运行
- 检查端口 8080 是否被占用
- 确认访问 `127.0.0.1` 而非其他地址

## 🔬 技术细节

### AES-256-GCM 加密流程
```python
1. 生成 32 字节（256-bit）随机 AES 密钥
2. 生成 12 字节随机 nonce
3. 使用 AES-GCM 模式加密助记词
4. 输出格式: nonce (12) + tag (16) + ciphertext (变长)
```

### Shamir 秘密共享
```python
1. 将 AES 密钥转换为十六进制字符串
2. 使用 (3, 5) 阈值方案生成 5 个分片
3. 每个分片是一个独立的字符串
4. 任意 3 个分片可重构原始密钥
```

### NTAG216 写入流程
```python
1. 生成 CardID (16 bytes 随机)
2. 生成 Counter (当前时间戳)
3. 生成 Challenge (32 bytes 随机)
4. 写入 CardID (Pages 4-7)
5. 写入 Counter (Pages 8-9)
6. 写入 Challenge (Pages 10-17)
7. 写入 Encrypted Blob (Pages 18-85)
8. 写入 Share (Pages 86-105)
```

### 卡片识别机制
```python
# 不使用 UID（可克隆），使用卡内数据
signature = {
    'card_id': read_pages(4-7),      # 16 bytes
    'counter': read_pages(8-9),      # 8 bytes
    'challenge': read_pages(10-17)   # 32 bytes
}
# 比较所有三个字段判断是否为同一张卡
```
